# 知识库文章模板使用说明

通用模板位于 `_templates/post.md`，适用于本项目的实验操作、源码解析和知识点笔记。它沿用现有的 `layout: post`、`title`、`category` 字段，以及图片的 `absolute_url` 写法。

模板放在 `_templates` 中，不作为 `_posts` 下的正式文章发布。使用时复制文件即可。

## 创建一篇文章

1. 将 `_templates/post.md` 复制到 `_posts/对应目录/YYYY-MM-DD-文章标识.md`，日期填写文章的实际日期。
2. 修改头部的 `title` 和 `category`，分类尽量复用已有名称，例如 `x86-assembly`、`qemu`、`os-6s081-source`、`golang知识点`。
3. 写好开头摘要，再根据文章类型删减章节、替换占位内容，最后调整章节编号。
4. 图片放到 `assets/分类/文章标识/`，替换图片示例路径，并补充有意义的图片说明。
5. 对照文末检查清单检查后，再按项目原有流程预览和发布。

例如，在项目根目录的 PowerShell 中创建一篇新文章（执行前将日期、文件名替换为实际值）：

```powershell
Copy-Item -LiteralPath '_templates/post.md' -Destination '_posts/x86assemb/YYYY-MM-DD-文章标识.md'
```

目标文件应是尚不存在的新文件，避免覆盖已有笔记。

## 根据文章类型裁剪

不必每篇都写满八节。保留“问题 → 解释或操作 → 验证或例证 → 结论”这条主线即可。

| 文章类型 | 建议章节 | 重点 |
| --- | --- | --- |
| 实验 / 环境搭建 | 目标、环境、必要原理、步骤、验证、排错、总结、参考 | 每一步有检查点，命令说明执行位置 |
| 源码解析 | 问题、源码版本、数据结构、调用流程、场景推演、总结、参考 | 指明文件和函数；区分原始源码、节选与简化代码 |
| 概念笔记 | 问题、核心概念、示例与边界、总结、参考 | 用一个具体例子解释机制，说明成立条件 |
| 故障记录 | 现象、环境、排查过程、根因、解决与复验、参考 | 保留报错和证据，区分事实与推测 |

例如，Golang Channel 原理可以把“实现过程”改为“发送与接收流程”，把“结果验证”改为“典型场景推演”，分别讨论不同状态下的行为。没有执行测试，就将结果标为推演，不写成实测。

## 汇编文章的套用示例

以 `_posts/x86assemb/2024-08-31-assm01.md` 为例，可以保留现有代码和截图素材，按下面的大纲重组。这是结构建议；具体技术内容与验证结果需要在整理文章时核对。

```text
标题：assembly-01-编译并在 Bochs 中调试汇编代码
摘要：说明如何将汇编程序编译成二进制文件，写入 VHD，
      配置 Bochs 启动，并通过断点和寄存器检查执行结果。

1. 实验目标
   说明从编写程序到运行调试的完整链路与验收条件。
2. 环境与准备
   记录宿主系统、NASM、VirtualBox、Bochs、写盘工具版本和文件位置。
3. 启动流程与关键概念
   解释本文启动方式下的引导扇区、签名和加载位置。
4. 实验步骤
   4.1 创建 VHD：记录格式与后续配置所需的信息。
   4.2 编写与编译：说明输入输出文件、代码作用和填充逻辑。
   4.3 检查二进制：记录文件大小、签名和检查方法。
   4.4 写入虚拟硬盘：说明目标文件，展示写入后的检查结果。
   4.5 配置 Bochs：把截图中的关键配置写成文字。
   4.6 启动与调试：区分启动日志、调试命令与实际观察结果。
5. 验证结果
   说明断点位置、执行到哪条指令，以及寄存器预期值与实际值。
6. 问题排查（有实际记录时保留）
7. 总结
   回答如何确认程序已被加载并执行。
8. 参考资料与关联笔记
```

原文的调试命令适合整理为“命令 / 用途 / 本次使用位置”表格；多张截图则紧跟对应操作，并写清“从图中要确认什么”。这样复习时可以直接查找步骤与结果。

## 写作约定

- **标题层级：** 页面主题已经显示文章标题，模板正文从 `##` 开始；步骤用 `###`，通常不超过三级。现有侧栏脚本读取二级标题，章节标题应具体且容易识别。
- **摘要：** 第一段说明问题、方法和结果，避免再写一遍标题。
- **代码：** 标注语言；将可执行命令与输出分开。引用源码时记录版本和位置，省略部分代码要说明，简化示例不要称为完整源码。
- **参数：** 对路径、端口、地址和版本等重要值解释含义；让读者知道哪些值需要自行替换。
- **图片：** 沿用 `{{ "/assets/分类/文章标识/图片.png" | absolute_url }}`，不要使用本机绝对路径。图片应辅助文字，关键命令和配置仍用文本保存。
- **证据：** “启动成功”“结果正确”后面补充输出、状态或数值；注明哪些已经验证、哪些只是推测。
- **关联：** 参考资料写明支撑的知识点；前置概念链接到已有笔记，减少重复解释。

## 发布前检查

- [ ] 文件名日期、标题、分类填写正确。
- [ ] 第一段说清问题、方法和结果。
- [ ] 已删除占位内容、示例路径、写作提示及不适用的章节。
- [ ] 版本、文件位置和关键配置足以支持复现或定位源码。
- [ ] 命令、代码和输出分开，代码块标注正确语言。
- [ ] 核心步骤有检查点，最终结论有证据或明确的推演说明。
- [ ] 图片及参考链接有效，截图旁有文字解释。
- [ ] 预览确认标题层级、目录、代码块、表格和图片显示正常。
